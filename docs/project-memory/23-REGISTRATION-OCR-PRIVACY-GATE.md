# 23 — Registration OCR: privacy, consent and live-readiness gate

**Status (2026-10-06): the gate is OPEN — automatic (external) reading of vehicle-registration documents is DISABLED everywhere.** `REGISTRATION_OCR_PROVIDER=disabled` on local, staging and production. The code that would send a document exists (local commits `f4dfef0` + the consent-gate commit on top of it) but refuses to run until every item below is complete and the three configuration keys are set. Nothing in this document is legal advice; the consent screen informs the provider and records their choice — it does not by itself make the processing lawful.

## 1. What is at stake (the exposure, stated plainly)

- A **photo or scanned PDF** of an Omani vehicle-registration card (mulkiya) is sent **in full** — the whole stored image (normalized, metadata-free JPEG) or the whole PDF — to the Anthropic Messages API when OCR is enabled. The card carries, besides vehicle data, the **owner's name, civil number, nationality, address** and possibly insurer/policy details. The instruction asks the model not to *report* those fields and the result type has no place for them, but **the pixels still leave BARQ infrastructure**. Output filtering is not input minimization.
- A **PDF with a text layer is never sent**: it is read locally and deterministically (tier 1). Only photos and image-only PDFs reach tier 2 (OCR).
- Nothing is sent without the provider's **recorded, document-bound, notice-versioned consent** (section 3) — this holds even when OCR is enabled.

## 3. What the code guarantees (so the checklist is about the rest)

- **Fail closed, three times**: the environment schema refuses to start with `claude` unless the key, the geography and the notice version are all set; the reader factory refuses at runtime unless the same are valid and the model is on the allowlist; the extraction service refuses to call without a current GRANTED consent for the exact stored bytes.
- **Standalone consent step** (not bundled into general terms) after upload, before any byte leaves: names the external AI processor, says processing is outside Oman (US / "US or other countries" per the configured geography), states the single purpose, that results may be wrong and the provider confirms, that declining is possible and never blocks the vehicle, the owner/authorized attestation, and what OCR does *not* do (verify ownership, approve the vehicle, replace BARQ review). Arabic (RTL) and English first; parity across all 8 locales.
- **Durable proof of consent** (`vehicle_registration_ocr_consents`, migration 66): provider id, authenticated user id, setup (asset) id, document id, SHA-256 of the exact stored bytes, decision (GRANTED/DECLINED), notice version, processor, purpose, disclosed geography, interface language, attestation flag, timestamp; append-only; survives cancellation (links SET NULL). Never the API key, never document contents or values. Audited (`vehicle.registration_ocr_consent_granted|declined`).
- **Decline = manual entry**, same shell, nothing sent; a later re-analysis still sends nothing.
- **Stale notice** (version changed) and **replaced document** (bytes changed) each require a fresh decision. One provider's consent never covers another provider's document.
- **Geography**: `inference_geo` is sent explicitly on every request; `usage.inference_geo` must equal it or the answer is discarded unread (`OCR_GEO_MISMATCH`); there is no fallback to global routing.
- **Data minimization status**: orientation correction and EXIF/metadata removal happen locally before storage (so the engine receives an upright, metadata-free image). **Deterministic cropping/masking of owner name, civil number, address, QR/barcode was NOT implemented**: the repository holds no representative, fully redacted Omani samples covering the known card layouts, and no real card may be used; a mask that is wrong for some layouts would produce a false "personal data removed" claim. The notice therefore discloses that the **complete** document may be processed. **Residual privacy risk: ACCEPTED ONLY WITH CONSENT — recorded here as an open item** for a later gate with redacted samples.
- **Abuse/cost controls**: see item 7. A provider cannot use the endpoint as a general vision proxy: the only input is a document they uploaded through the vehicle-document policy (type/size/signature checks), consented to, within budget, and the only output is the allowlisted field set.

## 4. Not done / honest limits

- No live Anthropic request has ever been made from this codebase (no credential). The adapter's request contract is tested against the vendor documentation and synthetic response shapes only.
- Reading accuracy on real Omani cards is unmeasured.
- The vendor documentation statements used here (retention tiers, ZDR by arrangement, Covered Models, `inference_geo` semantics, 1.1× pricing, US-only workspace geography) were read on 2026-10-06 and must be re-confirmed against BARQ's actual contract before enabling.
- Real-iPhone behaviour of the upload/consent flow is untested on hardware.
